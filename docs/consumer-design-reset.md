# C 端体验重新定向 · 2026-10-22

用户明确拒绝 V2 的表达和审美。功能验证不构成视觉接受；这轮先做独立的设计候选，不覆盖 V2 或生产。

## 错在哪里

V2 把“证据可查”的内部要求做成了页面主题。用户原本想理解分数，看到的却是工作台、知识关系、直接相连、前置/进阶记录、来源状态、复核提示、数据编号和存储状态。它解释系统怎样工作，却没有用足够大的图形解释知识。画布和侧栏重复标题；大量同等级小字与细边框没有清楚重心。深色加点阵并不自动带来审美。

需要区分：官网负责让人看到具体价值；学习页负责让人理解当前知识；来源与审核信息在需要核对时可打开；数据质量台账属于维护流程。重要限制仍需可见、可达，但不在每个区域重复。

## 实际参考

- [Heptabase 官方白板图](https://heptabase.com/_next/static/media/whiteboard-feature.dded7d9e.png)：浅灰工作面、白色内容、清晰阅读尺度；工具退到边缘；颜色表示内容分组。参考视觉层次和安静的画布，不复制它的全套研究工具。
- [Heptabase 官网](https://heptabase.com/)：围绕实际材料、白板与阅读场景呈现功能。官网研究不再只读功能列表，必须查看真实界面资产。
- [Brilliant 官方交互图](https://brilliant.org/_next/static/media/blake-1.2m3yhr8ri6zhl.png)、[官方页面](https://brilliant.org/)：一个具体数学操作占据主画面，说明和按钮服务这件事。参考图形、动手与反馈，不搬用其 AI 导师或学习效果主张。
- TheBrain 用于关系焦点切换；InfraNodus 用于进一步研究结构空白。这两个产品不作为本轮 C 端的视觉母版。

## 新设计只做一个清楚的承诺

**打开一个知识点，先看懂，再顺着联系探索。**

视觉：浅灰纸面、白色学习卡、石墨色文字、一个低饱和青绿色；让教学图形成为主视觉。主卡标题只出现一次，正文和数字足够大。周围的相关知识是可打开的内容卡，不是数据库节点方框。

内容：主屏只有当前概念、一个真实图解、简短解释和“试一题”。搜索、收藏、笔记在需要时打开。来源与内容状态集中在“内容说明”；暂停练习的概念在操作时明确说明。没有关系数量、数据 ID、常驻保存状态、英文装饰字、产品流程口号和假学习成就。

交互：点击相关卡换焦点；分数图可切换 1/4、1/2、3/4，数值与图形同步；练习在同一卡片里展开；来源、笔记、搜索使用可关闭的原生对话框。轻微位移、阴影与出现过渡只帮助分清可点击的对象。

范围：新增 `consumer.html` / `consumer.css` / `consumer.mjs`。全量概念来自现有数据；“分数、小数与百分数”和勾股图解是两个有限的手工设计样例，其余概念保留真实文字与关系。它用于验收产品表达和视觉方向，不主张全量教学内容已经重做。

官网后续应直接展示这一类真实学习场景，再补一句产品用途和进入入口；暂不新增一套口号式营销长页。先确认这张学习桌面的方向成立，再决定首页如何承接。


## 可以直接检查的设计约束

- 桌面以 510px 阅读卡为中心，侧卡 202px，列间 48px；低于 1100px 收起右列，低于 720px 改成主内容在前、相关知识在后的纵向布局。
- 系统中文字体；主标题 25px，正文 14px、行高 1.85；题干 19px。无装饰英文副标题。青绿色只用于动作、选中与图形，错误答案使用棕色反馈。
- 1280×720 的默认首屏可以看到“试一题”；390×844 无横向溢出，手机主要操作的点击高度至少 44px。
- 讲解、练习在同一卡片内切换。分数按钮同时更新图形、等式、解释；错误答案和参考答案分开标色，并给出文字反馈，不用颜色独自表达判断。
- 搜索、来源、笔记使用带名称的原生对话框；关闭后回到触发位置，键盘可操作，保留明显的焦点轮廓；尊重系统减少动态效果设置。
- 首次加载使用骨架；请求失败提供重试；找不到知识点可搜索；没有题目或暂停练习时说明当前能做什么。

## 本轮验证与边界

已实测桌面和 390px 手机页面：分数切换、错误和正确作答、收藏列表、笔记保存后刷新、相关知识切换和返回、手机搜索、来源和关系说明、暂停练习的拦截。修正了首屏动作位置、分数切换说明不同步、错误选项颜色、手机搜索按钮的无障碍名称。9 项核心回归测试与全量数据契约检查通过；构建为独立本地静态包。

未验证：真实学生是否愿意持续使用、学习是否改善、全量讲解和关系的学科正确性。界面验收不等于内容验收，也不等于用户接受视觉方向。没有改变旧页面入口、原始课程数据，也没有推送或部署。
