# V3.2 公网 UI/UX 3 倍镜评测报告

**评测对象**: https://vnbke2vo1l8z4.space.mcode.cn
**评测时间**: 2026-07-22
**评测工具**: Playwright 1.x + Chromium headless @ 1440×900 / 375×812
**数据集**: 1,906 节点 / 4,736 关系 / 14 学科
**评测人**: general-purpose agent (按"Open Curriculum CN V3.2 UI/UX 三倍镜评测专家" 角色执行)

---

## TL;DR

V3.2 整体已经达到"可用"水平 — 加载快、键盘可达、i18n 框架就位。但作为"教育数据可视化"产品, 它仍卡在"工程师视角"而不是"老师/家长视角"。最致命的不是缺功能, 而是:

1. **数据有但 UI 不用** — 4,736 条 `reason` 边、2,628 条 `relates_to` 软关联、1,906 个 `assessment_prompt` 模板, **全部埋没在 graph.json 里**; 用户从详情卡看不到任何"为什么这条关系存在"。
2. **移动端崩** — 概念地图按钮被搜索框完全遮挡, 在 iPhone 上根本点不到; 概念地图模式在手机上是空白屏。
3. **"1:1 复刻 Marble"但 Marble 是 3D 球, V3.2 是 2D 意大利面** — 1,906 节点挤在 1440×900 里, 视觉冲击远不如 Marble 主页。

下面 8 场景 + 35+ 问题 + 3 个最关键改进 + 5 个 3D 追赶方案。

## 场景评测

### 场景 1: 冷启动首屏 (Cold Start)

打开页面后 500ms / 1.5s / 3s 三个时间点都截图了。**首屏体验: 良好, 但缺进度条**。

- **DOM 加载**: 109ms
- **完整加载**: 取决于 graph.json, ~50ms
- **数据规模**: graph.json 317KB (gzip 后从 3.5MB 原始压下来, 9:1 压缩比) / cytoscape.min.js 373KB / app.js 43KB
- **Loading 状态**: 有 spinner + "加载知识图谱..." 文字 + `role="status" aria-live="polite"`, 但**没有进度条/百分比**, 用户在 3.5MB 下载时只能盯一个旋转图标
- **500ms 截图**: 已经能看到 header + 搜索框 + 空图区, spinner 在中央
- **1.5s 截图**: 图谱已大部分渲染

**截图**: `data/screenshots/v32-ux-01a_loading_500ms.png` `01b_loading_1500ms.png` `01c_first_screen.png`

### 场景 2: 概念地图模式 (V3.1 特色) ⭐

V3.1 的杀手锏。表现**中规中矩, 有亮点也有硬伤**。

- **切换按钮**: 在右上 stats 面板里, 文字"概念地图", 位置 {x:1318, y:172} 在桌面端 OK; 但**移动端见场景 6**
- **树结构**: 14 学科 → 44 学段 → 241 领域 → 1906 概念, 层级清晰
- **"全部展开"按钮**: 工作, 1906 概念全部展开, 树可以滚动
- **搜索联动**: 输入"万以内", graph 端高亮 3 个蓝点 (search-hit class); **但树端没有视觉提示**哪些节点匹配, 用户要在 1906 个概念里盲找
- **"只看本分支"按钮**: 切换文字 (从"只看本分支" → "显示全部"), 行为正确
- **分支高亮实测 bug**: 点 "万以内数的认识" 后, 整个图除了那 1 个点之外都 opacity:0.15 (几乎不可见)。**用户想要"专注本分支但保留上下文"**, 实际拿到"全黑屏 + 1 个亮点" — 这和"概念地图"想体现的"全谱浏览"价值背道而驰

### 场景 3: 概念详情卡 ⭐⭐⭐ (问题最严重)

点击"万以内数的认识"看卡片。**这是整个产品最该详细的页面, 也是问题最集中的页面**。

实测卡片渲染的字段:
- ✅ 标题 (万以内数的认识)
- ✅ 学科 · 学段 · 领域 (数学 · G1-2 · 数与运算)
- ✅ Tags: bloom 维度 (了解/理解/知道) + 难度 (●○○○○) + 时长 (15 分钟) + subdomain (数的认识)
- ✅ 内容要求 + 课标原文链接 (P25)
- ✅ 学业要求 (空, 数据里也是 null, OK)
- ✅ 知识要点 (5 条)
- ❌ **assessment_prompt 完全没显示** — 数据有"在数学课上, {{name}}能否理解「万以内数的认识」..."这种 3 段式提问模板, 老师最想要的"怎么考这个概念", UI 端一个字没显示
- ❌ **reason 字段 (边) 完全没显示** — 4,736 条数据都有, 比如"学低年级的「数位与位值」是同段「万以内数的大小比较」的直接基础", **这正是家长/老师最想看的"为什么这个先决"**
- ❌ **relates_to 软关联 (2,628 条) 完全没展示** — 实测"万以内数的认识"的先决里混进了"信息与信息社会" (信息科技) 和"认识周围的植物" (科学) 这两条**跨学科软关联**, 用户无法分辨"硬先决 vs 软关联", 会误以为数学依赖生物课
- ❌ 移动端打开卡片本身没问题 (375×812 全屏), 但详情卡里的"查看下游 3 层"按钮 (1 个) 显得单薄, 没有"查看上游"对照

**截图**: `v32-ux-03a_card_wannei.png` `03b_card_mobile_375.png`

### 场景 4: 键盘快捷键 (9 个)

9 个全部测试, 8 个工作, 1 个有条件工作。

| 键 | 结果 | 备注 |
|---|---|---|
| `/` | ✅ 聚焦搜索框 | |
| `1`-`9` | ✅ 切换第 N 个学科 | 9 个全过 |
| `0` | ✅ 全部学科切换 | 0→14 隐藏 |
| `l` | ✅ 标签显隐 | "显示标签" ↔ "隐藏标签" |
| `r` | ✅ 入口高亮 | window._rootsHighlighted toggle |
| `R` | ⚠️ 触发但无 DOM 反馈 | 用户看不到发生了什么 |
| `Esc` | ✅ 关 card / 清搜索 | 优先级正确 |
| `?` | ✅ 打开 modal | **但**搜索框聚焦时失效 (按设计) |
| `?` (input 内) | ❌ 不响应 | 用户被锁在搜索框里, 看不到帮助入口 |

**关键问题**: `?` 在 input 聚焦时按设计不触发, 但页面上**没有持久可见的 "?" 按钮提示有快捷键**, 用户第一次来根本不知道有快捷键。**键 `?` 按钮**虽然存在, 但只藏在 stats 面板角落里, 移动端直接被遮 (见场景 6)。

**截图**: `v32-ux-04a_kbd_modal.png`

### 场景 5: i18n 切换 (zh-CN / zh-TW / en)

UI 框架 (stats / 按钮 / 卡片标题 / 树标题) 切换正常, **但概念数据本身有 2 个硬伤**。

- **zh-CN → zh-TW**: UI 文字完美翻译 ("概念数" → "概念數", "概念地图" → "概念地圖")。**但概念标题翻译漏字**:
  - `万以内数的认识` → `萬以內數的認**识**` (最后 "识" 没转, 简体字典漏字)
- **zh-CN → en**: UI 文字完美 ("Concepts", "Concept Map", "Edges"), **但 1,906 个概念标题全是中文** (因为数据只有中文, tConcept() 对 en 没实现)
  - 结果: 一个英国用户看到全屏中文字符的图, 没有任何线索这是什么

**截图**: `v32-ux-05a_lang_zh_tw.png` `05b_lang_en.png`

### 场景 6: 移动端响应式 (375×812) ⭐⭐⭐ (问题集中)

iPhone viewport 下, **多个关键交互崩**。

| 元素 | 位置 (x,y,w,h) | 问题 |
|---|---|---|
| header | (0,0,375,80) | 占首屏 1/10, 副标题 2 行文字 |
| stats | (10,70,355,89) | **吞掉 159px** 高度, 比 header 还大 |
| search | (10,130,355,33) | y=130, 占据第 2 排 |
| **#toggleMode** | **(194,129,58,22)** | **y=129, 与 search input (y=130) 重叠 21px, click 落到 search input** ❌ **概念地图按钮点不到** |
| langSwitch | (270,12,94,22) | 与 header "2022 新课标知识图谱" 标题右上重叠 |
| legend | (10,694,355,108) | 占底部 108px, 14 个 chip 两行多, 部分被切 |

**移动端概念地图模式**:
- 开启后, `body.map-mode` 触发 CSS `margin-left: 280px`, 让 cy-container 偏移
- 但 cy-container 仍是 `width: calc(100% - 280px)` = `100% - 280px` = `375-280` = **95px**
- **实测 cy-container 实际位置**: x=280, y=0, w=375, h=812 (不是 95!)
- 因为 CSS 是基于 body (375) 算的, 而 body 在 map-mode 下没动, 所以 cy-container 跑到 viewport 外
- **用户在手机上看到**: 左边 280px 是树 (可滚), **右边 95px 是图, 实际是 95px 的图 + 280px 的空白屏**
- **手机概念地图 = 几乎不可用**

**移动端详情卡**:
- 正常打开, 占满屏幕 (375×812) OK
- 但卡片内"查看下游 3 层"按钮在底部, 滚动到底才能看到

**截图**: `v32-ux-06a_mobile_initial.png` `06b_mobile_map_mode.png` `06c_mobile_card.png` `06d_mobile_card_scrolled.png`

### 场景 7: 可访问性 a11y

整体 a11y 框架**做得不错**, 但有 1 个 WCAG AA 失败和 1 个硬编码问题。

- **Skip link**: ✅ 有 `.skip-link`, 跳到 `#cy-container`
- **ARIA labels**: ✅ cy-container `aria-label="概念关系图, 758 节点, ..."`, card / search 都有
- **Tab 路径**: 从 lang 按钮 → 4 个 stats 按钮 → 搜索 → 学科 chips, 顺序合理
- **无图无 alt 缺失**: ✅ `imgsMissingAlt: 0`
- **无标签按钮**: ✅ `buttonsMissingAriaLabel: 0`
- **对比度**:
  - 主文字 (#e6e9f2 vs #0a0d18) = **15.97:1** ✅ AAA
  - 副文字 (#8a92a8 vs #0a0d18) = **6.24:1** ✅ AA
  - 弱文字 (#5a6278 vs #0a0d18) = **3.19:1** ❌ **WCAG AA 要求 4.5:1, 大字 3:1, 弱文字小于 12px 时不达标** (用于 "暂无先决" 等提示)
- **硬编码 ARIA**: `cy-container aria-label="概念关系图, 758 节点"`, 实际 1,906 节点, 屏幕阅读器用户得到错误信息
- **概念地图模式 header 被遮挡**: header z-index:10, map-panel z-index:15, 280px 宽的 panel 把 header 标题盖住 (见场景 2 截图)

**截图**: `v32-ux-07a_a11y_keyboard_focus.png` `07b_focus_state.png`

## 35 个 UX 问题 (按 P0/P1/P2 分)

### P0 — 必修, 影响核心价值或功能不可用 (12 个)

#### P0-1: 概念详情卡完全没显示 `assessment_prompt` 字段
- **场景**: 3
- **复现**: 打开 https://vnbke2vo1l8z4.space.mcode.cn → 搜索"万以内" → 点击"万以内数的认识" → 看卡片右栏
- **现状**: 卡片有"内容要求 / 学业要求 / 知识要点"3 个 block, 但数据里的 `assessment_prompt` (3 段式提问模板, 含 `{{name}}` 占位符) 一字未显
- **影响**: 老师/家长最想看的"怎么考这个概念"完全缺失, 这块数据是 V3.x 数据采集的核心增量
- **截图**: `v32-ux-03a_card_wannei.png`
- **修法**: 在 showCard() 里新增 `assessment-prompt` block, 替换 `{{name}}` 为默认值"学生"或卡片顶部 input

#### P0-2: 边的 `reason` 字段 (4,736 条) 完全不显示
- **场景**: 3
- **复现**: 同样, 详情卡"直接先决"/"解锁后继"列表
- **现状**: 列表只显示 `title + grade`, 但 `edge.reason` (如"学低年级的「数位与位值」是同段「万以内数的大小比较」的直接基础") 全文 0 字符
- **影响**: 用户不知道为什么这个先决, 信任度低, 家长最常问"为什么数学要学这个"
- **截图**: `v32-ux-03a_card_wannei.png`
- **修法**: 改 `fillRows()`, 在 row 下面加一行小字 `.reason` 文字 (灰色, 11px, line-clamp 2 行)

#### P0-3: 跨学科软关联 `relates_to` (2,628 条) 完全不展示
- **场景**: 3
- **复现**: 详情卡"万以内数的认识"的"直接先决"列表, 实测混入了"信息与信息社会"(信息科技) 和"认识周围的植物"(科学) 两条**软关联**, 边 rel 都是 `hard`, **因为 cytoscape edges 数据里 `type` 全是 hard** (代码 line 254: `e.type === 0 ? 'soft' : 'hard'`, 但实际数据 type 是字符串 'hard'/'soft'/'relates_to', 判断条件错)
- **影响**: 误把"软关联"当"硬先决"展示, 让用户以为数学课需要先学生物
- **截图**: `v32-ux-03a_card_wannei.png`
- **修法**: (a) 修 edges 加载时的 `type` 转换 (`e.rel === 'relates_to' ? 'soft' : 'hard'`); (b) 在先决/后继列表里把 hard/soft 分两栏或加图标

#### P0-4: 移动端 `#toggleMode` 按钮被搜索框完全遮挡
- **场景**: 6
- **复现**: 打开 DevTools 切到 iPhone viewport (375×812) → 找"概念地图"按钮
- **现状**: 按钮在 y=129, 搜索框在 y=130, 重叠 21px; **实测 click 落到 search input, 按钮 click 不到**
- **影响**: **移动端用户无法进入概念地图模式**, 整个 V3.1 特色功能对手机不可用
- **截图**: `v32-ux-06a_mobile_initial.png` (按钮在图右中, 但 search 覆盖了它)
- **修法**: 移动端把 stats 面板的"概念地图"按钮提到 header 第二排, 或合并成一个 FAB 浮动按钮

#### P0-5: 移动端概念地图模式 = 几乎不可用
- **场景**: 6
- **复现**: 移动端点击"概念地图" → cy-container 跑到 viewport 外
- **现状**: CSS `body.map-mode #cy-container { margin-left: 280px; width: calc(100% - 280px); }`, 实际 `100% = 375px`, 所以 cy-container 应该是 95px, **但实测渲染是 375px 宽 (基于 absolute 定位 + transform)**, 整个图推到 x=280-655 区间, viewport 只看到 0-95px
- **影响**: **手机端概念地图模式整个图区是空白**
- **截图**: `v32-ux-06b_mobile_map_mode.png`
- **修法**: 移动端 map mode 应是"树全屏 + 浮动按钮回到力导向", 而不是左右分屏

#### P0-6: zh-TW 简繁字典漏字 "识"
- **场景**: 5
- **复现**: 切到繁體 → 任意概念标题
- **现状**: `万以内数的认识` → `萬以內數的認**识**` (最后"识"未转换)
- **影响**: 繁體用户看到半简半繁, 不专业
- **截图**: `v32-ux-05a_lang_zh_tw.png` (右上 stats: "概念數"✅, 但卡片里字未转)
- **修法**: 完善 `web/simp_to_trad.js` 字典, 或改用成熟的 opencc-js 包

#### P0-7: EN 模式概念标题仍是中文 (1,906 条)
- **场景**: 5
- **复现**: 切到 EN → 看图, 全部节点是中文
- **现状**: UI 文字 (stats / buttons / 树标题) 都翻译了, **但 `window.tConcept()` 对 en 直接返回 `title_orig` (中文)**, 因为数据没有 en 翻译
- **影响**: 国际用户 (如海外华人学校) 看到全屏中文, 无任何英文线索
- **截图**: `v32-ux-05b_lang_en.png`
- **修法**: (a) 短期: EN 模式下显示 Pinyin (`pypinyin` 已装在 venv); (b) 长期: 接 PaddleNLP 翻译或人工补译

#### P0-8: ARIA label 硬编码 "758 节点" (实际 1,906)
- **场景**: 7
- **复现**: 用 VoiceOver/NVDA 读 cy-container
- **现状**: index.html line 282 `aria-label="概念关系图, 758 节点, 14 学科, ..."` 写死, 实际加载 1,906 节点
- **影响**: 屏幕阅读器用户得到错误信息, 且无 fix 提示
- **截图**: `v32-ux-07a_a11y_keyboard_focus.png`
- **修法**: 加载完成后, JS 动态更新 `cy-container.setAttribute('aria-label', \`概念关系图, ${nodes.length} 节点, ...\`)`

#### P0-9: 分支高亮 = 几乎全黑屏
- **场景**: 2
- **复现**: 概念地图模式 → 展开数学 → 1-2 年级 → 数与运算 → 点"万以内数的认识"
- **现状**: `branch-hl: 1, branch-dim: 1906` (实测), 1905 个非相关节点 opacity:0.15, **用户看到全黑图, 只能看到 1 个点**
- **影响**: "只看本分支" 按钮的命名暗示"突出显示本分支", 实际是"全屏变黑"
- **截图**: `v32-ux-02d_map_concept_clicked.png`
- **修法**: (a) 把 dim 改成 0.3-0.4 而不是 0.15; (b) 用 "仅本分支" 按钮时, 把非本分支节点 opacity 设 0.05 + 边 opacity 0.05, 本分支 + 1-2 层邻居 opacity 1.0

#### P0-10: 概念地图模式 header 被树遮挡
- **场景**: 2
- **复现**: 进入概念地图模式 → 看左 280px 区域
- **现状**: header z-index:10, map-panel z-index:15, **map-panel 完全覆盖了 header 的左 280px** — "2022 新课标知识图谱"标题和"Open Curriculum CN · 1:1 复刻 Marble" 副标题在树后面看不到
- **影响**: 用户进入概念地图模式后, 失去页面身份感, 不知道这是哪个产品
- **截图**: `v32-ux-09_header_behind_tree.png`
- **修法**: map-panel 加 `top: 80px` (header 高度), 或 header z-index 提到 20

#### P0-11: 概念地图模式 search input 与 tree panel 重叠
- **场景**: 2
- **复现**: 概念地图模式 → 搜索框仍占据 left:20, top:80, width:320 → 但 tree panel 在 left:0, top:0, width:280
- **现状**: 260px 重叠, **search 中心最顶层是 map-tree**, 所以用户点 search 框的右半部分会触发 tree 的 click

## 3 个最关键改进 (按 ROI 排序)

### 改进 1: 详情卡补全 `assessment_prompt` + `reason` + 软关联区分
- **现状**: 详情卡是用户停留时间最长的页面, 但 3 个最有教育价值的数据字段全没用
- **修法 (3 个 P0 一起修)**: 
  - showCard() 新增 `card-assessment-prompt-block` 块, 替换 `{{name}}` 为 input 或默认"学生"
  - fillRows() 在 row 下面加 `<div class="row-reason">${e.data('reason')}</div>`, line-clamp 2
  - 改 edges 加载时的 type 映射 (`e.rel === 'relates_to' ? 'soft' : 'hard'`)
  - 软关联 row 加半透明背景 + 🔗 图标区别
- **预期效果**: 用户得到"为什么 + 怎么考"双视角, 老师/家长最关心的信息全到位
- **工作量**: 1.5 人天

### 改进 2: 移动端布局重做 (3 个 P0 一起修)
- **现状**: 移动端 4 个元素重叠 / 概念地图模式空白屏
- **修法**:
  - 移动端把 stats 按钮 + 概念地图按钮合并到 header 第二排 (或 FAB)
  - map mode 移动端改成"树全屏 + 返回力导向 FAB"
  - 树顶 search 位置改成 top: 0 在 map panel 内部
  - legend 改成底部可折叠抽屉
- **预期效果**: 手机用户可正常浏览, 不再是"桌面端缩水版"
- **工作量**: 2 人天

### 改进 3: zh-TW 字典 + EN 翻译补全
- **现状**: 繁體漏字, 英文模式全屏中文
- **修法**:
  - `web/simp_to_trad.js` 换成 `opencc-js` npm 包 (支持 s2t 完整映射)
  - EN 模式: 用 pypinyin (后端) 或 pinyin-pro (前端) 临时方案, 同时后台开英译任务
  - 短期: EN 模式显示 `中文 (Pinyin)` 格式, 如 `万以内数的认识 (wàn yǐ nèi shù de rèn shi)`
- **预期效果**: 港台 + 海外用户可用, 不再是"国内版"
- **工作量**: 0.5 人天 (字典) + 持续 (英译)

## 5 个 3D 视觉追赶方案

Marble 主页 (https://withmarble.com/curriculum/) 用 Three.js 3D 球体, 14 门学科作为经度分区, 概念作为球面上的点, 拖拽旋转, 滚轮缩放。视觉冲击 1:10 强于 V3.2 当前的 2D 网格。

V3.2 不需要完全照搬 Marble, 但**必须有 1-2 个"哇"时刻**。以下 5 个方案按实现难度/效果比排序:

### 方案 A: 力导向图升级成 "球面分块 + 学科地球" (推荐, 性价比最高)
- **思路**: 保留 2D cytoscape, 但节点**位置按学科分布在同心圆 / 球面投影**, 数学在最内圈 (基础学科), 信息技术在最外圈 (跨学科应用)
- **具体**:
  - 用 `d3-geo` 的 azimuthal 投影, 把节点按 `centrality` 映射到经纬度
  - 学科用经度分块 (每 360/14 ≈ 25.7°), 学段用纬度分 (1-2年级近北极, 7-9年级近南极)
  - 边用 curve 沿球面, 而非直线
- **视觉冲击**: 从 7/10 升到 9/10
- **工作量**: 3 人天
- **数据需求**: 已有 (subject + grade_start + centrality)

### 方案 B: "概念探险"模式 (P5 探索式导航)
- **思路**: 不动主图, 但在详情卡里加一个"概念探险"模式, 进入一个 3D 小球, 显示当前节点 + 1-2 层邻居, 用户可以旋转看
- **具体**:
  - 详情卡底部加 "🔮 进入 3D 探险" 按钮
  - 用 `three.js` 渲染一个 200x200 的 mini 球, 当前节点在中心, 邻居在球面
  - 边用 curve + 流动粒子 (Marble 主页的标志)
- **视觉冲击**: 详情卡内局部体验从 5/10 升到 8/10
- **工作量**: 2 人天
- **数据需求**: 用 BFS 取 2 层邻居, 已有

### 方案 C: "学段球" 启动动画
- **思路**: 加载时, 不要直接显示意大利面, 而是从中心 1 圈 → 14 圈展开, 像一个花球绽开
- **具体**:
  - cy 加载完后, 节点按 stage 1-4 分层 z 坐标
  - 用 d3-force 跑 5 秒收敛动画, 配 easing `cubic-out`
  - 镜头从 0.5x 缩放推到 1.0x
- **视觉冲击**: 首屏体验从 6/10 升到 8/10
- **工作量**: 0.5 人天 (一个 d3-force 动画 + cy.fit 动画)

### 方案 D: 学科色 → 学科地形 (2.5D)
- **思路**: 不上 Three.js, 但用 cytoscape 的 `shape: round-rectangle` + `background-fill` 模拟"地块"
- **具体**:
  - 同色学科节点聚在一起形成一个"国家", 用 force 调高 intra-group 吸引
  - 不同学科用不同形状 (数学=圆, 语文=方, 艺术=星)
  - 边用 curve 跨组时变粗
- **视觉冲击**: 6/10 → 7.5/10
- **工作量**: 1 人天
- **缺点**: 仍不是真 3D, 视觉冲击有限

### 方案 E: "学习路径" 3D 浮窗
- **思路**: 用户点"查看下游 3 层"时, 不在 2D 上画 path, 而是从当前节点弹出一个 mini 3D 球
- **具体**:
  - 详情卡"查看下游 3 层"按钮 click 后, card 顶部展开一个 300x300 的 canvas
  - 显示当前节点 (中心) + 3 层 BFS 节点 (球面), 用户可旋转
  - 边用动画粒子
- **视觉冲击**: 路径可视化从 5/10 升到 9/10
- **工作量**: 2.5 人天

**推荐组合**: A (主图升级) + C (启动动画) + E (路径 3D)。 总工作量 ~6 人天, 视觉冲击 1:10 缩小到 ~1:3。

## 结论

V3.2 是一个**有真实数据的可用产品**, 但有 **12 个 P0** 和 **13 个 P1** 问题需要解决。最该优先做的 3 件事是:

1. **详情卡补全 3 个核心字段** (assessment_prompt / reason / soft 区分) — 让产品从"图谱"升级为"教辅"
2. **移动端重做** — 当前移动端约等于不可用
3. **i18n 修字典** — 繁體漏字 + 英文模式全屏中文, 让产品出不了国门

3D 视觉追赶建议方案 A (球面分块) + 方案 C (启动动画), 6 人天投入可大幅提升首屏冲击力。
