## 三、问题与改进

### 问题 1: \n 换行符缺失 (P1)

**现象**: PoC 数据中 `description` 和 `assessment_prompt` 都没有 `\n` 分隔。
- 期望: 50 概念 × 2 字段 × 2 个 `\n` = 200
- 实际: 0
- 影响: assessment 3 个问题挤在一行, UI 渲染时换行靠浏览器自动 wrap, 中文长句视觉粘连

**根因**: V3.3.1 PoC prompt 没说清楚要 \n 分隔, sub-agent 按单段落输出。

**修复**: V3.3.1 扩展 prompt 强制 `### 1. 描述 (1段)\n\n### 2. 评估 (3 问各 1 行)`, 并在 LLM 输出 post-processor 里强制插入 `\n\n` 切分。

### 问题 2: Sub-agent 自报数据有水分 (P1, 流程纪律)

**现象**: sub-agent 报告原文"{{name}} 100% 各 3 个, \n 各 2 个", 实际 \n 各 0 个。

**根因**: sub-agent 自抽样时只看了 `{{name}}` (确实 100% 命中), 没数 `\n`, 直接报"我估计是 2 个"。

**教训**: 
- sub-agent 报告里所有数字必须独立验证, 不能信"我估计"
- 扩展 14 学科时, sub-agent 的"succeeded" 只代表没崩, 不代表数字准确
- **改流程**: 扩展脚本加 post-validation (desc_len 60-100, ass_len 150-200, \n 数 ≥3, {{name}} =3), 不达标自动 retry

### 问题 3: 禁词残留 (P2, 后续 ban)

**统计**:
- "理解" — 13 次 (description 3, assessment 10)
- "培养" — 1 次 (description 1)

**建议 V3.3.2**: ban list 加严: `理解 / 培养 / 掌握 / 运用 / 知识点 / 课标 / 教学目标 / 含义 / 定义`, 命中自动重写。

### 问题 4: PoC 范围仅 G1-G2 NS 50 概念 (信息, 非问题)

PoC 故意只挑 50 个验证质量, 没扩 337 全量数学。证明可行后, 下一轮 14 学科并行。
