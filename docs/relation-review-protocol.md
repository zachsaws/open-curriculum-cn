# 前置关系人工审核协议

本协议只决定一条 `prerequisite` 边能否进入**学生诊断建议**。它不删除图谱中的探索性关系，也不以 AI 互审代替学科教师审核。

## 审核标准

审核者须对 `from → to` 独立回答：在目标学段与学习目标下，学生若尚未掌握 `from`，是否通常无法理解、完成或评估 `to`？

- 是：可考虑通过为 `prerequisite`。
- 只是主题相近、同单元、可迁移、后续延伸或跨学科启发：不通过；应保留为 `relates_to` 或 `progresses_to`，不进入诊断。
- 无法由课标、教材或正式教学目标支持：不通过，保留待审。

## 最小审核记录

每一条通过边必须写入 `web/data/relation_reviews.json` 的 `reviews`：

```json
{
  "edge_id": "EDGE_ID_FROM_GRAPH_LITE",
  "evidence_source": "教育部 2022 义务教育课程标准（学科名）",
  "evidence_locator": "页码、学段、具体条目或教材章节",
  "reviewer_role": "八年级数学一线教师",
  "reviewed_at": "2026-09-17",
  "rationale": "说明为何 from 是达成 to 的必要基础，而非相关主题"
}
```

`edge_id` 必须存在于部署图谱，且该边的 `rel` 必须为 `prerequisite`。CI 会阻止缺少来源、定位、审核角色或日期的记录进入部署。

## 最小流程

1. 从同一学科、同一学段抽取候选边；审核者先独立判断，不看系统推荐结果。
2. 记录证据定位和判断理由；拿不准则不加入 `reviews`。
3. 两位教师对同一批边意见不一致时，保留冻结，记录分歧，不以多数投票替代证据。
4. 每次新增审核记录后运行 `python tools/validate_learning_quality.py`；通过后才允许该边进入学生建议。

## 不可主张的边界

审核通过表示“该关系可作为复习候选”，不表示孩子答错目标题就一定是该前置概念未掌握，也不表示该建议已产生学习效果。学生层面的诊断效度仍须另做教师盲评、迁移题与保持测试。
