# Open Curriculum CN：现状评审与 V2 定义

评审日期：2026-10-22。基线：`dc75a4bf034a306f442fe6aa770e13c0bb292013`。用户已确认仓库，并确认先做 K12 概念学习工作台。本文在实现前形成；交付记录另见 `V2-validation.md`。

## 判断

**值得继续验证一个小而完整的学习产品；尚不能称为可靠的学习诊断系统，更没有证据证明商业模式已成立。** 已有价值是中文课标概念与关系的公开探索、按概念组织的讲解和练习。最有希望的差异不是 3D 球或大题库，而是“让家长、学生和教师知道一条关系为什么存在，并用可核对的练习继续学习”。

当前用户跨度过大。首要假设用户应收敛为：和孩子一起回看某个概念、但不知道怎样解释或怎样继续的家长；教师作为内容共建与审核者。高年级学生可独立使用。这只是待验证的用户假设，不是访谈结论。低年级儿童独立操作、大规模教研 SaaS、通用个人知识 OS 暂缓。

阶段定位：课程数据和交互实验 → 一个可使用、可被专业人员核对的学习闭环。不能把公开可访问、数据校验通过、界面可用等同于学习有效。

## V2：可核对的概念学习工作台

一句话定义：围绕正在学习的概念，在同一工作区理解讲解、查看关系依据、做一小组题并留下可回看的学习记录。

北极星路径：**找到正在学的概念 → 看懂直接关系 → 核对一条关系或来源 → 作答并读解析 → 记录待复习/笔记 → 返回原概念继续。**

候选北极星指标：每周完成这一闭环、并能解释一条关系的有效学习会话数。点击节点、停留时间、题量不作为理解的替代指标。正式埋点前，先在获同意的可用性测试中观察；不在本轮新增外部追踪。

范围：保留所有数据和旧入口；新增独立 `learn.html`。先支持全量概念搜索/学科年级筛选、直接邻域、关系理由、来源状态、现有题目选择题精确判分、题后解析、局部复习记录与个人笔记。跨学科关系默认关闭，按需探索；待复核前置可供查看，但不能生成确定的补弱路径。无前置记录应写“暂无收录”，不能推断“不需要基础”。

取舍：暂缓通用知识 OS、资料上传、自动矛盾发现、AI Tutor、账户同步、付费、教师后台、全量内容改写、另一套 3D 动效。不要在未验证题目/关系上扩大自动生成规模。笔记与自测记录不是知识审核；用户“理解了”不能改写成“已掌握”。

## 模型演进

本轮只加轻量派生关系文件和独立本地状态，不迁移旧数据。

目标模型：`Concept` 保持稳定 ID；`Relation` 保存 from/to/type、具体 rationale、SourceSpan IDs 与审核结论；`Source` 保存发布者/版本/URL/内容指纹；`SourceSpan` 保存原文、页码类型、偏移/锚点及核对状态；`Exercise` 保存答案契约、来源类型和教师审核状态；`Attempt` 保存题目 ID、题目版本、原作答、时间和结果；`LearningNote` 保存个人理解；`ViewState` 只保存焦点与布局。数据语义和画布位置分离。

状态至少区分：AI/OCR 整理、来源已核对、教师已复核、争议/暂停。不能通过“有 reason”“source=curriculum”或 review_round=3 自动升级状态。未来审核应分别记录内容、年级适配和关系，不用一个 reviewed 布尔值遮盖差异。

## 分阶段验收

1. **本轮 V2 交互验证**：独立分支可运行；原页面不变；真实数据驱动；检索、关系检查、来源、自测解析、记录和恢复完整；桌面/窄屏/键盘及失败状态检查通过。只证明实现可用。
2. **有限内容试点**：由用户/教师选定一个学习目标，再审核约 20–40 条相关关系和约 30 道有区分度题目；逐条来源可定位；至少两种表征与迁移任务。不把本轮演示概念当作已批准教学试点。
3. **学习验证**：与真实目标用户做有同意的任务观察；查看能否解释关系、即时迁移和 7 天保持，记录失败原因。样本量与效果标准由试点方案预先约定；不足不报有效率。
4. **发布候选**：用户视觉验收、专业内容验收、发布数据门槛、自动化路径回归与部署依赖完成后，再由用户决定是否上线。商业化放在有重复使用与价值证据之后。

当前最应停止的工作是扩题量和扩关联数量；最应投入的是降低“看起来有依据、实际上未核对”的信任成本。
